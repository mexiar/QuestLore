# QuestLore

<img src="media/questlore-icon-400.png" width="160" alt="QuestLore: an open book beneath a golden quest marker">

**Understand why your character is doing a quest.** QuestLore adds short narrative context to your active quest in World of Warcraft: Forever, in English, neutral Spanish, or Simplified Chinese.

[Download the latest release](https://github.com/mexiar/QuestLore/releases/latest) · [Report an issue](https://github.com/mexiar/QuestLore/issues) · [Polestar integration](docs/POLESTAR.md)

## What it does

- Shows the story behind the quest selected in your quest journal or followed through the quest tracker.
- Includes **5,259 bilingual quest narratives** across the audited catalog, including Forever-specific quests, without a level cap.
- Explains the current assignment using information available at that step. The editorial review removes later chain outcomes and unsupported interpretations.
- Introduces a new level-one character through a single story combining race and class. There are 90 defensive variants per language, including faction-specific Skyborne variants; this does not mean all 90 combinations are playable.
- Keeps up to **200 unique stories per character**, accessible exclusively in **Options → AddOns → QuestLore → Story history**, or through **View history** in the main options panel.
- Reads archived stories separately from live Lore. Selecting an old story never replaces the current quest in the tracker.
- Works locally: no AI service, external request, subscription, or machine translation during play.

## Interface

The transparent **Lore** section uses a yellow quest title and white narrative text. In the tracker and portrait layouts, the quest title and narrative use the same configured font size. Its only header control minimizes or restores the section and stays visible when attached; when detached it appears only while hovering Lore, including the collapsed title bar. There are no page arrows, history counters, Current button, or title tooltip in the live window. Escape leaves Lore open.

Lore attaches below the quest list by default when **ForeverCore** exposes its shared tracker API. It follows the tracker width and visibility. You can detach it in the options, then drag the header to move it or the lower-right corner to resize it. The resize icon appears only while hovering the detached window and stays visible during resizing. Long narratives scroll; the scrollbar disappears when the text fits. Collapsing other tracker sections triggers a deferred reflow so Lore can reclaim the released space. Its desired height is measured at the full text width, independently of the previous scrollbar gutter. Text is measured without stale height constraints so the full narrative remains available instead of ending in an ellipsis. Attachment changes requested during combat wait until combat ends.

Language, font size, attachment preference, detached position and size, visibility, minimized state, and history are saved per character. Existing explicit detachment settings are respected.

## Wide detached layout

Detach Lore in the addon options, then drag the lower-right corner. When the **expanded window is wider than it is tall**, it automatically becomes a compact horizontal banner:

- The quest name replaces **Lore** in the header, centered in the same native header typography and yellow color.
- The title is not repeated above the narrative.
- Narrative paragraphs use full justification; the last line of each paragraph remains left aligned.
- The window can be made shallow (about 80 UI units minimum, with extra room when a long header or large font needs it) and has **no addon-imposed maximum width**. The client's display and frame constraints still apply.
- Text remains scrollable if it cannot fit. Minimizing preserves the expanded aspect ratio, title, and saved dimensions.

This layout is useful above action bars or across the top of the screen. Making the detached window square or taller restores the ordinary Lore header and separate quest title. Reattaching always uses the tracker layout. Position and dimensions remain per character.

## Installation

1. Download `QuestLore-0.16.3.zip` from Releases.
2. Extract the **QuestLore** folder into `_forever_/Interface/AddOns/`.
3. Check that `Interface/AddOns/QuestLore/QuestLore.toc` exists, without a second nested QuestLore folder.
4. Enable QuestLore in the game's addon list. Restart the client for a new installation; use `/reload` when updating an existing installation.

This release targets **Forever interface 16001**, based on client **1.60.1.70938**. It is not verified for Retail or other Classic clients. **ForeverCore is optional**: standalone Lore works without it; tracker attachment requires it. Polestar is not required.

The source-code ZIP generated by GitHub contains repository documentation and tests. Use the **QuestLore release ZIP** for installation.

## Options and language

Open **Options → AddOns → QuestLore** to choose:

- **Automatic**, **Español**, **English**, or **中文**. Automatic selects Spanish for `esES`/`esMX`, Simplified Chinese for `zhCN`/`zhTW`, and English for every other game locale.
- The Chinese narratives are machine-assisted translations of the English text (local Qwen3 8B, with DeepSeek rewrites of flagged entries), using official zhCN names for people, places and creatures. In Chinese, the quest title comes from the game client.
- Narrative text size, **12–24**, with a live preview and reset to **14**.
- Whether to attach below the quest tracker.
- **View history**, opening the history subcategory with a scrollable title list and full story reader.

Changing language also updates available archived narratives. History retains completed and abandoned quests, reuses one entry per quest, and preserves its first position. Duplicate entries from older versions are merged automatically. Hidden or minimized narratives are not archived as newly read stories.

The opening race/class story appears only for a new level-one character with no quests or history. Once the adventure starts, an empty quest log does not restart that introduction. It remains available in history if it was previously shown.

## Commands and key bindings

| Command | Action |
| --- | --- |
| `/lore` or `/questlore` | Show Lore |
| `/lore reset` | Reset the detached window position |
| `/lore refresh` or `/lore actualizar` | Retry loading the active quest |
| `/lore fuente 14` | Set narrative text size |

The game's Key Bindings panel includes actions to show Lore, scroll its text, open story history, and change font size. QuestLore assigns no keys automatically. The live section always follows the quest context; archive navigation lives in the options.

## Coverage and editorial limits

The audited catalog contains **5,413 records**: **5,259 bilingual narratives**, **154 documented exclusions**, and **zero pending narratives**. It combines 5,410 records from the installed Forever quest database with three supplementary published quest records whose current in-game availability is unverified. Catalog inclusion is not a promise that every quest is currently obtainable by every character.

The full editorial pass reread every narrative in both languages and all 90 opening variants. It corrected 400 quest rows and three opening combinations for fluency, neutral Spanish, narrative clarity, supported motivation, and current-step chronology. Sparse exchanges or automatic rewards receive a concise account of their documented purpose rather than an invented backstory.

Known quest IDs use curated narratives. An unknown or altered quest may fall back to available quest text, a loading state, or a missing-story notice. That fallback is not counted as a curated narrative. Report an incorrect title, translation, spoiler, or missing quest with its quest ID, game locale, and the text visible when accepting it. Avoid posting personal SavedVariables files.

## Polestar

**Options → AddOns → QuestLore → Follow Polestar's active quest** enables direct, event-based following. The option defaults to on and is saved per character. Polestar remains optional.

When enabled, Lore reads the accepted quest associated with Polestar's current navigation target, including area/search objectives and turn-ins. It subscribes once to target changes, reads the target after quest-log updates (including accepting, completing, or removing quests), and checks once per second as recovery for missed or delayed messages. Unchanged targets do not cause repeated window redraws. It does not change Polestar's route, waypoints, or quest tracking.

While the option is enabled and Polestar has a valid accepted quest, **Polestar takes priority** over another quest selected automatically by the game or manually in the journal. This prevents accepting a side quest from leaving Lore on that quest while the guide continues elsewhere. Turn off the option to follow your own quest selection. Acceptance recommendations, unaccepted quests, manual pins, missing targets, missing or incompatible APIs, and removed quests fall back to ordinary journal/super-tracked/watched quest selection. Disabling the option cancels the safety timer, removes the subscription and immediately restores ordinary selection. This controls the direct bridge; native super-tracking can still reflect changes made by Polestar itself.

See [integration details and tested limits](docs/POLESTAR.md).

## Development

The addon uses Lua 5.1 and the game's UI APIs without bundled libraries. Runtime source and the editable narrative tables are in `QuestLore/`. `Narratives.lua` contains the bilingual quest corpus; `Origins_Stories.lua` contains the integrated opening variants. `tests/run.lua` simulates quest APIs, events, history, options, layout, and asynchronous loading. `tests/layout.lua` checks 590 geometry cases across all font sizes (12–24), three tracker widths, three space budgets, both languages, paragraphs, long tokens, minimize/restore, and detached resizing. `tests/horizontal.lua` adds 312 cases for automatic mode transitions, native header typography, full justification without lost text, shallow/wide geometry, saved dimensions, and pool reuse. It independently derives the native viewport from recorded anchors and tests delayed range updates, last-line reachability, reading-position preservation, and idle convergence. It also checks every narrative ID across supported language selections and seven client locales.

Requirements: **Python 3** and **Lua 5.1**.

```sh
python3 tools/package.py --lua lua5.1
```

The public packaging command validates runtime Lua, XML, TOC agreement, and the test suite, then creates `dist/QuestLore-<version>.zip`. It uses the checked-in, editable Lua corpus and does not require the author's private research workspace or quest caches. The original research-generation pipeline is separate from this public packaging path.

Automated tests simulate the client; they do not replace in-game visual or gameplay verification. Changes to client APIs may require compatibility updates.
